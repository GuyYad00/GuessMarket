# LMSR — Logarithmic Market Scoring Rule (נספח א')

שיטת מסחר לא-הדדית: קונים "מול חשבון האירוע", לא מול מוכר אחר.
בתרגיל 1: בדיוק 2 אפשרויות לכל אירוע. כל מניה זוכה משלמת $1 בסוף; מפסידה — $0.

## מושגים
- `q_yes`, `q_no` — כמות המניות שנרכשו עד עכשיו מכל אפשרות.
- `b` — מדד נזילות (מספר שלם חיובי, מוגדר ב-XML). b גבוה = מחיר זז לאט; b נמוך = תזזיתי.

## נוסחה 1 — שווי אפשרות (מחיר)
```
p_yes = e^(q_yes/b) / ( e^(q_yes/b) + e^(q_no/b) )
p_no  = 1 - p_yes   (תמיד משלימים ל-1)
```
בתחילת אירוע (q=0,0): כל אפשרות שווה 0.5.

## נוסחה 2 — הקופה (cost function)
```
C(q_yes, q_no) = b * ln( e^(q_yes/b) + e^(q_no/b) )
```

## עלות קנייה
```
cost = C(after) - C(before)
```

## דוגמה מהמסמך (לאימות המימוש!)
b=100, מצב התחלתי (0,0), קניית 100 מניות YES:
- לפני: `C(0,0) = 100 * ln(2) = 69.31`
- אחרי: `C(100,0) = 100 * ln(e^1 + 1) = 131.33` (במסמך: 131.32)
- עלות הקנייה: `131.32 - 69.31 = 62` (כ-0.62 למניה)
- מחיר YES אחרי הקנייה: `e^1/(e^1+1) = 0.73` (ו-NO = 0.27)

## סבסוד (Subsidy)
- `C(0,0) = b*ln(2)` — זהו הסבסוד שה-MM "משקיע" בהקמת האירוע.
- בתרגיל 1, בטעינת קובץ תקין: "חשבון מנהל האירועים מתאפס. כמו כן יש לעבד את סבסוד
  כלל אירועי ה-LMSR המוגדרים בקובץ."
- **החלטת מימוש (סופית)**: חשבון האירוע מתחיל ב-**0** בטעינה. כל קנייה מוסיפה
  לחשבון את עלותה (+עמלת on-purchase), ובסגירה משלמים לזוכים מהחשבון.
  אימות מול הדוגמה במסמך: b=100, קנייה 62.01, YES זוכה → חשבון = 62.01-100 = ‎-37.99‎,
  וזה בדיוק הסבסוד נטו שה-MM הוציא לפי המסמך (השקיע 69.31, הזדכה על 31.32).
  תואם להבהרת המרצה: "אם היא שלילית — זה הסכום שה-MM נדרש בפועל להוציא כדי לסבסד;
  אם חיובית — זה מה שהרוויח".
  (חלופה שנפסלה: להתחיל את החשבון ב-b*ln(2) כ"קופה" — אז היתרה בסוף לעולם לא
  שלילית, כי C(q) תמיד ≥ מהתשלום לזוכים, בסתירה מפורשת לדברי המרצה.)

## עמלות (commission) — אחוז שלם 0..90
- **on-purchase**: בכל קנייה מוסיפים לקונה עמלה = `cost * C%` על התשלום הסופי.
  המשתמש משלם `cost + fee`; ה-fee עובר לחשבון האירוע (בנפרד מ-cost שגם נכנס לחשבון).
- **on-close**: נגבית רק בסגירה, מהזוכים בלבד. לפי המסמך: "יש לנקות מסכום ההשקעה
  הכולל באפשרות הזוכה את אחוז העמלה ולהעבירו לחשבון האירוע. מהסכום שנותר משלמים
  לכלל הזוכים על פי כמות המניות שרכשו."
  **פרשנות מימוש** (מגובה בסימולטור של המרצה: "every winning share pays $1 minus
  commission, if on close"): התשלום לזוכים = `q_winner * $1 * (1 - C%)`,
  והעמלה `q_winner * $1 * C%` נשארת/נזקפת לחשבון האירוע.
- "סה"כ עמלה שנגבתה בפועל עד לשלב זה" (פקודה 3) — לצבור מונה עמלות נפרד לכל אירוע.

## סגירת אירוע — סדר הפעולות
1. המשתמש בוחר אפשרות זוכה.
2. אם on-close: גובים עמלה מסך תשלומי הזוכים (ראה למעלה) לחשבון האירוע.
3. משלמים לזוכים ($1 לכל מניה זוכה, בניכוי עמלת on-close אם רלוונטי) מחשבון האירוע.
4. **לא מאפסים את החשבון** — היתרה נשארת (יכולה להיות שלילית!).
5. האירוע מסומן "סגור" — אי אפשר לקנות בו יותר.
